# ZHANDI - 战术FPS游戏

基于Web的多人战术射击游戏，使用Three.js、Rapier物理引擎和WebSocket实现。

## 技术栈

- **渲染引擎**: Three.js
- **物理引擎**: Rapier3D (WASM)
- **网络通信**: WebSocket
- **构建工具**: Vite
- **编程语言**: TypeScript

## 当前功能状态

> 状态说明：**已接入**表示当前游戏流程可实际使用；**原型级**表示有可运行闭环但尚未达到生产质量；**仅有代码**表示存在类或配置，但没有完整接入当前玩法。

| 系统 | 状态 | 说明 |
|---|---|---|
| Rapier 物理与第一人称移动 | 原型级 | 已接入 60 Hz 固定步长、可靠地面/坡度检测、动态蹲姿碰撞体、头顶阻挡、冲刺、跳跃、体力、FOV 和坠落伤害 |
| 武器系统 | 原型级 | 已接入 STG44、Suomi、MG42、Kar98k，支持分段伤害衰减、姿态散布、拉栓/换弹事件和弹道模拟；正式骨骼动画仍缺失 |
| 征服模式 | 原型级 | 已接入部署、倒计时、战斗、结算、重开，以及 A/B/C 据点争夺、兵力值和安全出生评分 |
| AI | 原型级 | 分阵营 Bot 已接入感知记忆、距离 LOD、墙体/烟雾视线约束和可解释小队战术；导航图与长局验收已有自动化基础，仍需实机 16v16 性能验证 |
| 地图与资源 | 原型级 | 当前仍使用120×120程序化废墟灰盒；已建立统一地图定义、显式实例组、GLTF/GLB + Meshopt加载、Draco/KTX2配置入口和分阶段资源清单，正式原创模型/贴图尚未提供 |
| 战术装备 | 原型级 | 破片、烟雾和闪光弹已接入 |
| 载具 | 原型级 | 当前战局生成两辆可驾驶吉普；载具武器和模块化伤害未形成闭环 |
| 天气与昼夜 | 已接入 | 晴、雨、雪、雾、沙尘和昼夜变化可运行，尚未与材质和 AI 感知联动 |
| 音频 | 原型级 | 当前使用 WebAudio 合成占位音，支持基础 HRTF 空间化 |
| HUD/UI | 已接入 | 菜单、设置、计分板、准星、血量、弹药、小地图和征服信息可用 |
| WebSocket 联机 | 原型级 | 当前主要同步位置；远端插值、权威命中、房间、断线恢复尚未完成 |
| 预测/反作弊/网络优化 | 仅有代码 | 存在对应类，但没有形成当前在线玩法的可信完整链路 |
| 排位与成就 | 部分接入 | 成就逻辑已接入部分事件；排位系统未进入正式战局流程 |
| 性能监测 | 已接入 | F3 显示 FPS、P50/P95、draw calls、三角形、资源与实体数，可导出 JSON |

详细改造路线见 [`优化计划/仿战地5分阶段优化计划.md`](优化计划/仿战地5分阶段优化计划.md)。

## 安装与运行

### 安装依赖

```bash
npm install
```

### 开发模式

```bash
npm run dev
```

### 质量检查

```bash
npm run check
```

该命令依次执行格式检查、ESLint、TypeScript 类型检查、Vitest 和生产构建。

### 固定基准场景

在开发地址后添加 `?benchmark=1`，例如：

```text
http://localhost:5173/?benchmark=1
```

基准模式使用固定随机种子、8 个 Bot、2 辆吉普和固定晴天。按 `F3` 打开性能面板，可导出性能 JSON。

当前模拟采用固定 60 Hz 时间步，渲染保持 RAF 刷新率；长帧最多追赶 5 个模拟步。Esc 或页面失焦会进入暂停状态并重置累计器，避免恢复页面时集中补帧。

### 构建生产版本

```bash
npm run build
```

### 预览生产版本

```bash
npm run preview
```

## 性能与网络说明

- 当前已经配置 Vite 代码分包、部分特效池以及可导出的实时性能监测。
- LOD、实例化渲染、动态分辨率与资源流送仍属于待生产化功能。
- 当前联机服务器只承担基础 WebSocket 消息转发，不是权威战斗服务器。
- 客户端预测、插值、压缩和反作弊类尚未形成完整接入链路，请以“当前功能状态”表为准。
